# BlindBoxTravelAI Phase 1 数据契约与验收

本次工作针对用户指定的 34 个省级行政区、100+ Spots、50+ Routes。
- **标签文件审计**：实际条目数、去重数与声明数分别统计，禁止自造新标签以冒充“500”。
- **盲名**：原名称中只取两个汉字保留；每个其余汉字严格替换为一个星号，不删尾缀、不动长度。
- **暴露检查**：description、summary_100w、每个 strong tag 的 tag_interpretation，以及每日 blind_highlights 均不能含 full_name 或维护在敏感词表中的破盲别名。省份、城市可以保留。
- **事实字段**：null + 原因比编造价格、开放时间与图片更好；0 元只表示已核实免费。证据 URL 描述该来源可支持的事实，不用登录墙结果当证据。
- **坐标**：小数经纬度、来源及精度；不宣称绝对零误差。
- **天气**：mock_weather 仅是季节性静态参考，不是实时预报；出发安全、台风/潮汐/高反情况需用当日权威信息复核。
- **隐私**：攻略只提公共路线知识；不收用户昵称、账号 ID、头像、联系信息或个人主页。
- **渠道真实性**：五类指定源要独立记账；未能取得 Mac 携程 APP/封闭移动社媒数据时不得标已完成全渠道爬取。
- **路线**：single_spot 1–2 天且唯一景点；multi_spot 2–7 天至少两个景点；每日节点与 spot_ids 必须存在；行程为基于公开资料的编辑合成不等同实测轨迹。
- **进化计数**：spots/routes 每个 ID 均有 plan_mark_count=0、review_count=0，不能记录用户来源。
- **入库**：先 `python3 scripts/validate_blindbox_seed.py .` 本地数据零结构错误后同步，并单独报告外部事实的更新日期与失效复核项目。

## 交付状态规则
- 结构校验 PASS 不等于票价、图片或官网覆盖完成；数据源声明要与实际 source_refs 分类一致。
- 同一景点的别名复用同一个 ID；路线新节点必须构造成独立景点、补齐基本结构和真实公开地理来源。
- 已核事实与未核字段分开：逐条票据、当季优惠、公共图片与实时天气仍须出发前查看权威最新发布。
